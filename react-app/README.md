# Дорожная карта изучения React: от базы к продвинутой архитектуре

* **Формат:** 1.5–2 часа в день (через день, с правом на пропуск).
* **Структура занятия:** 45 минут — глубинная теория (internals), 45–60 минут — изолированная практика руками.

---

## Фаза 1. Базовый переход и фундаментальная теория (Дни 1–14)

### Неделя 1: Ментальная модель, JSX и базовые хуки

- [ ] **День 1: Архитектура React и JSX**
  - **Теория:** Трансляция JSX в вызовы функций (`React.createElement` / `_jsx`). Virtual DOM как дерево легковесных JS-дескрипторов. Концепция $UI = f(State)$.
  - **Практика:** Развернуть проект (`npm create vite@latest react-deep-dive -- --template react-ts`). Написать компонент без JSX (только через `React.createElement`), затем переписать на JSX. Реализовать передачу компонентов через `children` и render props.

- [ ] **День 2: `useState` и концепция Immutability**
  - **Теория:** Поверхностное сравнение ссылок (`Object.is`). Батчинг обновлений (Automatic Batching). Функциональный апдейтер: разница между `setCount(count + 1)` и `setCount(prev => prev + 1)`.
  - **Практика:** Создать компонент с глубоко вложенным стейтом (объект с массивами объектов). Реализовать обновление полей без мутаций через spread-оператор. Симулировать race condition в стейте через `setTimeout`.

- [ ] **День 3: `useRef` — выход за пределы цикла рендеринга**
  - **Теория:** Механика ref под капотом (стабильный объект `{ current: T }` между вызовами функции). `useState` против `useRef`. Прямой доступ к DOM-узлам.
  - **Практика:** Написать таймер с сохранением ID интервала в `useRef`. Сделать инпут с управляемым фокусом и плавным скроллом к элементу. Реализовать паттерн хранения предыдущего значения пропса через `useRef`.

- [ ] **День 4: `useEffect` — модель синхронизации**
  - **Теория:** Почему `useEffect` — не аналог `ngOnInit`/`Form_Load`. Концепция синхронизации с внешними API/DOM. Механика функции очистки (cleanup function).
  - **Практика:** Реализовать подписку на `window.addEventListener('resize')` с обязательной отпиской в cleanup. Написать запрос к API через `fetch` с отменой через `AbortController`.

- [ ] **День 5: Ловушки `useEffect` и замыкания (Stale Closures)**
  - **Теория:** Механика замыканий в JS внутри функциональных компонентов. Устаревшие замыкания (Stale Closures) в таймерах и обработчиках. Роль массива зависимостей.
  - **Практика:** Искусственно воспроизвести баг устаревшего замыкания в `setInterval`. Исправить его двумя путями: через функциональный `setState` и через связку с `useRef`.

- [ ] **День 6: `useContext` — передача контекста через дерево**
  - **Теория:** Решение проблемы «prop drilling». Проблема каскадных ререндеров: почему изменение одного поля в контексте перерисовывает всех потребителей хука.
  - **Практика:** Создать контекст авторизации или темы оформления. Написать обёртку-хук с проверкой контекста на `null` с выбросом типизированной ошибки при вызове вне провайдера.

- [ ] **День 7: Практикум недели — Кастомные хуки**
  - **Теория:** Инкапсуляция логики состояния без разделения самого состояния. Правила хуков (Rules of Hooks).
  - **Практика:** Написать и протестировать кастомные хуки:
    - `useDebounce<T>(value: T, delay: number): T`
    - `useLocalStorage<T>(key: string, initialValue: T)`
    - Собрать компонент поиска с отложенным вводом.

### Неделя 2: Продвинутая механика рендера и внутренности React

- [ ] **День 8: Алгоритм согласования (Reconciliation) и Fiber**
  - **Теория:** Зачем создавался движок Fiber (прерываемый рендеринг, кооперативная многозадачность). Структура Fiber-ноды (`child`, `sibling`, `return`). Double Buffering (`current` vs `workInProgress`).
  - **Практика:** Найти и исследовать Fiber-ноду через Chrome DevTools (свойства `__reactFiber$...` на реальном DOM-элементе).

- [ ] **День 9: Ключи (`key`) и идентификация состояния**
  - **Теория:** Как алгоритм диффинга использует `key`. Почему использование индекса массива `key={index}` ломает состояние компонентов при удалении/сортировке.
  - **Практика:** Создать динамический список с инпутами с `key={index}`, удалить первый элемент и зафиксировать баг смещения значений. Исправить на стабильные UUID. Применить изменение `key` для полного сброса формы.

- [ ] **День 10: Фазы Render и Commit, `useLayoutEffect`**
  - **Теория:** Render Phase (чистая, асинхронная, может перезапускаться) против Commit Phase (синхронная мутация реального DOM). Разница между `useEffect` и `useLayoutEffect`.
  - **Практика:** Воспроизвести мерцание интерфейса при вычислении координат тултипа в `useEffect`. Устранить проблему переходом на `useLayoutEffect`.

- [ ] **День 11: Оптимизация вычислений — `useMemo` и `useCallback`**
  - **Теория:** Ссылочная целостность в JS. Назначение `useMemo` (кэширование результата) и `useCallback` (кэширование ссылки на функцию). Накладные расходы на мемоизацию.
  - **Практика:** Написать компонент с тяжелой фильтрацией массива (100 000 записей), замерить время через `console.time`. Оптимизировать через `useMemo`.

- [ ] **День 12: Мемоизация компонентов — `React.memo`**
  - **Теория:** Поверхностное сравнение пропсов (`shallow compare`). Почему инлайн-объекты `{}` и стрелочные функции ломают `React.memo`.
  - **Практика:** Создать дочерний компонент с логированием рендера. Проверить потерю мемоизации при передаче немемоизированных коллбэков и восстановить её через `useCallback`.

- [ ] **День 13: Обработка ошибок — Error Boundaries**
  - **Теория:** Почему ошибки в фазе рендера размонтируют всё дерево приложения. Классовые методы жизненного цикла `componentDidCatch` и `getDerivedStateFromError`.
  - **Практика:** Написать переиспользуемый компонент `ErrorBoundary` на классе. Обернуть в него изолированный нестабильный виджет, оставив остальной UI рабочим.

- [ ] **День 14: Итоговый проект первой фазы**
  - **Практика:** Собрать интерактивное файловое дерево (папки/файлы) с функциями создания, переименования, сворачивания и поиска. Использовать только чистый React, строгий TypeScript и кастомные хуки (без внешних библиотек).

## Фаза 2. Индустриальный стек (Дни 15–35)

### Неделя 3: Серверный кэш (TanStack Query) и клиентский стейт (Zustand)

- [ ] **Дни 15–16: Разделение Server State и Client State**
  - **Теория:** Почему хранить данные API в глобальных сторах — антипаттерн. Понятие кэша удаленного состояния.
  - **Практика:** Установить `@tanstack/react-query`. Реализовать выборку данных через `useQuery`. Настроить и протестировать параметры `staleTime` и `gcTime`.

- [ ] **Дни 17–18: Мутации и Optimistic Updates**
  - **Теория:** Изменение серверных данных через `useMutation`. Инвалидация ключей кэша (`invalidateQueries`). Механика оптимистичных обновлений с откатом (rollback).
  - **Практика:** Сделать переключатель статуса сущности с мгновенным обновлением UI и симуляцией сетевой ошибки с откатом к исходному значению.

- [ ] **Дни 19–21: Клиентский стейт с Zustand**
  - **Теория:** Архитектура Zustand: работа вне контекста React, интеграция через `useSyncExternalStore`. Селекторы стейта и предотвращение лишних ререндеров.
  - **Практика:** Создать глобальный стор для UI (сайдбары, модалки, активные фильтры). Настроить выборку через селекторы: `const open = useStore(s => s.open)`. Подключить middleware `persist` (`localStorage`) и `devtools`.

### Неделя 4: Промышленные формы и UI-архитектура

- [ ] **Дни 22–24: Неконтролируемые формы с React Hook Form**
  - **Теория:** Контролируемые (`value` + `onChange`) против неконтролируемых (`ref`) компонентов. Проблема просадки FPS при вводе в больших формах.
  - **Практика:** Реализовать форму через `useForm` и регистрацию `register`. Обернуть кастомный селект в `Controller` для работы со сторонними библиотеками.

- [ ] **Дни 25–26: Схемная валидация через Zod**
  - **Теория:** Type Inference: вывод TypeScript-типов из схемы валидации (`z.infer<typeof schema>`). Защита границ приложения (runtime validation).
  - **Практика:** Описать строгую схему формы в Zod (числа, email, вложенные объекты, кастомная валидация зависимых полей через `.refine()`). Связать схему с формой через `@hookform/resolvers/zod`.

- [ ] **Дни 27–28: UI-архитектура и Compound Components**
  - **Теория:** Паттерн составных компонентов (Compound Components). Инкапсуляция общего контекста группы элементов.
  - **Практика:** Разработать переиспользуемый компонент вкладок (`Tabs`, `Tabs.List`, `Tabs.Trigger`, `Tabs.Content`) на Compound-паттерне.

## Фаза 3. Продвинутый уровень и масштабирование (Дни 36–50)

### Неделя 6: Профилирование и оптимизация производительности

- [ ] **Дни 36–38: Профилирование с помощью React DevTools**
  - **Теория:** Анализ Flamegraph и Ranked диаграмм. Поиск причин частых обновлений («Why did this render?»). Замена мемоизации композицией («Push State Down», передача через `children`).
  - **Практика:** Создать искусственно замедленное приложение с тяжелым списком. Локализовать узкие места через React Profiler, устранить их реструктуризацией дерева компонентов.

- [ ] **Дни 39–40: Виртуализация списков**
  - **Теория:** Ограничения DOM при отрисовке больших объемов данных. Принцип скользящего окна (Windowing / Virtualization).
  - **Практика:** Подключить `@tanstack/react-virtual`. Реализовать плавный виртуализированный скролл таблицы на 20 000 строк.

- [ ] **Дни 41–42: Разделение кода (Code Splitting)**
  - **Теория:** Механика разбиения бандла на чанки (Chunk Splitting). Динамические импорты `import()`.
  - **Практика:** Реализовать ленивую загрузку маршрутов и тяжелых модальных окон через `React.lazy` и обертку `Suspense` со скелетоном.

### Неделя 7: Архитектура Next.js и React Server Components (RSC)

- [ ] **Дни 43–45: React Server Components (RSC) против Client Components**
  - **Теория:** Разделение среды исполнения: выполнение компонентов на сервере без отправки JS-кода клиенту. Разница между SSR и RSC. Границы директивы `'use client'`.
  - **Практика:** Развернуть проект на Next.js (App Router). Создать Server Component с прямым чтением данных из файловой системы или защищенного API без раскрытия ключей на клиенте.

- [ ] **Дни 46–48: Server Actions и Data Fetching**
  - **Теория:** Устранение сетевых каскадов (waterfalls). Server Actions как RPC-вызовы напрямую из форм и обработчиков. Ревалидация кэша путей.
  - **Практика:** Написать компонент с загрузкой данных через нативный `async/await`. Сделать форму с мутацией через Server Action и обновлением данных через `revalidatePath`.

- [ ] **Дни 49–50: Систематизация знаний и подготовка к интервью**
  - **Теория:** Повторение ключевых тем:
    - Модель согласования (Reconciliation) и Fiber.
    - Механика хуков и замыканий.
    - Client State vs Server State.
    - Оптимизация производительности: мемоизация против архитектурной композиции.
    - RSC vs классический SSR.
