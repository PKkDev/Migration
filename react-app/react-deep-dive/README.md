## React + TypeScript + Vite

### Virtual DOM

Это дерево таких объектов. При обновлении React строит новое дерево, сравнивает со старым и вносит в реальный DOM минимум правок. Важное уточнение, которое часто упускают: Virtual DOM не быстрее прямой работы с DOM. Его ценность в декларативной модели: вы описываете, как UI должен выглядеть, а не как его менять шаг за шагом. Время платите за сравнение деревьев.

### $UI = f(State)$

Компонент это чистая функция от состояния и пропсов. Когда состояние изменилось, React вызывает функцию заново и получает новое описание UI. Отсюда следствия, которые развернёт День 2:

1. локальные переменные внутри компонента сбрасываются при каждом вызове;
2. нельзя менять DOM вручную поверх React;
3. тело компонента не должно иметь побочных эффектов.

## useState

https://habr.com/ru/companies/otus/articles/667706/

useState — хук, который позволяет сохранять состояние внутри компонента. Возвращает массив из двух значений:
текущее состояние (1) и функция для его изменения (2).

Состояние хранит React (внутри своей структуры для компонента), а не переменная функции.
Функция компонента вызывается при каждом рендере заново, и состояние (1) каждый раз получает значение из хранилища React.
Поэтому состояние (1) внутри одного рендера константа: это снимок (snapshot)

функция для его изменения (2) не меняет переменную, а просит React отрисовать компонент заново с новым значением

```ts
const [count, setCount] = useState(0);
```

## Как React решает, перерисовывать ли компонент: Object.is

React сравнивает старое и новое состояние через Object.is(old, new). Если результат true, перерисовки нет.
Примитивы сравниваются по значению, объекты и массивы по ссылке. Отсюда главное правило React:
`Не изменяйте состояние на месте. Создавайте новый объект/массив.`

```ts
const [cart, setCart] = useState({ items: [], total: 0 });

cart.total = 100; // мутация: ссылка та же
setCart(cart); // Object.is(old, new) === true → перерисовки НЕТ
```

## Батчинг (Automatic Batching)

https://dev.to/shivamjjha/batching-in-react-4pp3

Начиная с React 18 все обновления состояния, вызванные в одном «тике» (обработчик клика, setTimeout, Promise, fetch), собираются в одну перерисовку:

```ts
function handleClick() {
  setA(1);
  setB(2);
  setC(3);
  // перерисовка будет ОДНА, после завершения обработчика
}
```

В React до 18 батчились только обработчики событий, в таймерах и промисах каждый set вызывал отдельный рендер.

setState - асинхронная функция. Под капотом реакт объединяет все мутации состояний, благодаря чему код функционального компонента будет вызван 1 раз, это называется "batching"
