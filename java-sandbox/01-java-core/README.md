### Почему Integer 128 == 128 даёт false, а 127 == 127 даёт true, и как проверить, что кэш настоящий?

При автоупаковке компилятор вызывает Integer.valueOf (x). Этот метод для значений от -128 до 127 возвращает заранее
созданные объекты из внутреннего массива (IntegerCache), а для остальных создаёт новый объект при каждом вызове. == на
двух Integer сравнивает ссылки: для 127 обе переменные указывают на один и тот же кэшированный объект, для 128 на два
разных

### Чем Float.MIN_VALUE отличается от float.MinValue в C#?

В Java Float.MIN_VALUE равен 1.4E-45, это наименьшее положительное число. В C# float.MinValue равен -3.4028235E+38
(самое отрицательное), а 1.4E-45 там называется float.Epsilon. Аналог float.MinValue в Java: -Float.MAX_VALUE. Причина:
знак у float и double хранится отдельным битом, диапазон симметричен, поэтому отдельного «минимума» нет, а для целых
типов (дополнительный код) MIN_VALUE обычный.

### Почему в Java нельзя написать метод swap (int a, int b)?

Аргументы всегда передаются по значению: метод получает копии a и b, и если поменять их местами внутри, исходные
переменные вызывающего кода не изменятся. Для объектов копируется ссылка, и реассайн копии (s = new ArrayList<>()) тоже
не виден снаружи.

В C# есть ref / out, которые передают саму переменную, в Java их нет. Чтобы поменять значения, нужно вернуть обе из
метода (record или массив) или изменять поля объекта-контейнера.
